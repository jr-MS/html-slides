现状

成本烧得快,往往不是"用得多"

上下文过载

全仓引用、超长会话,输入 token 被无关信息撑大。

低质量返工

核心思路

先提质量,成本自然下来。
盲目省 token,只会把钱花在反复试错上。

少而准

更少调用、更高成功率,自动减少 token。

每个 token 有用

目标不是数 token,是让每个 token 产生价值。

误差会复利

多步流程里,单步小误差累积成大返工。

04
第一性原则

上下文:尽可能少,但必须够

过少

信息缺失

缺关键背景时模型"补脑",幻觉概率上升。

刚好

精准命中

只给任务真正相关的部分,质量最高、最省。

过多

噪声污染

无关信息让模型分不清主次,被带偏、答错。

别默认塞全仓,剩下的让 agent 按需自取。

管住上下文窗口

别让窗口悄悄"跑偏"

已用 65%
0%窗口占用越高,越只盯最近内容100%
  • 模型偏好开头和结尾,中间内容容易被忽略(lost-in-the-middle)。
  • 超过一半后,会越来越忘掉最初的指令。
  • 一个任务一个干净窗口;换任务就 /clear 重开,别硬拐弯。

把提问写准

不是写更短,是首轮就锚定正确

copilot · prompt
✗ "帮我修个 bug" # 找错地方,来回返工 ✓ "按 issue #45 复现,修复 auth/token.ts, 让 tests/auth.spec 全过即停" # 多几个 token,省一整轮误判
  • 已知的文件/文档位置直接给,别让 agent 反复找。
  • 写明停止条件,避免过度操作。

确定性护栏

测试,是最强的省钱手段

bash — npm test
$ npm test ✓ auth/token.spec.ts (12) ✓ api/routes.spec.ts (8) ✗ billing.spec.ts (1 failed) # agent 自动定位并回修 Tests 20 passed · 护栏把跑偏拉回正轨

测试 / lint / 安全扫描——越早拦截,越省后续返工。没有护栏,错误会层层叠加。
