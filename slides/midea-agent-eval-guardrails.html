Customer-specific standards

标准指标之外，还要评估“美的自己的标准”

2

LLM-based evaluator + code-based evaluator

  • 业务语义判断答案是否符合场景、流程、角色和业务口径。
  • 确定规则检查字段、格式、权限、步骤、阈值等硬性约束。
  • 红队测试上线前主动挑战越狱、prompt injection、敏感信息和危险输出。
  • 回归资产把失败样本沉淀为 eval dataset，持续复用。
05 / 07
04
RAI / Guardrails

Evaluation 发现风险，Guardrails 在运行时防住风险

Input

输入防护

识别 jailbreak、prompt injection、恶意请求和不合规意图。

Grounding

事实防护

要求回答基于可信知识源；低 groundedness 时拒答、降级或提示不确定。

Tools

动作防护

高风险 tool/action 加权限、策略、确认步骤，防止越权执行。

Output

输出防护

内容安全、敏感信息保护、引用依据、合规检查和审计记录。
