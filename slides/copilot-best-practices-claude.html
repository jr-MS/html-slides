01 · Status Quo

四个让团队 不敢全力依赖 的痛点

在动手解决之前，先把问题摆桌上、按"模型 / 上下文 / 网络 / 调试"四象限分类。

P.02 / 19
PAIN · 01 / MODEL

GPT 系列"看不懂整个项目"

让它扫描整个 OA 项目生成新需求代码，结果给的是更加混乱的代码。

本质：模型上下文不足 + 项目隐性规则缺失。

PAIN · 02 / ACCESS

Claude 在管理后台已配置，IDE 选不到

想用 Claude Code 跑业务代码，编辑器里就是没有它。

本质：Policy / Editor / 缓存 / 计划层级未对齐。

PAIN · 03 / LATENCY

响应慢，疑似网络问题

同样的 prompt，有时几秒、有时几十秒，团队不确定是不是代理问题。

本质：网络 routing / 模型负载 / 上下文体积。

PAIN · 04 / DEBUG

接手他人 bug，AI 定位不准

让 AI 帮忙找 bug，给出来的位置跟最终修复点对不上。

本质：缺少 grounding · 没有引用调用链与堆栈。

03 · Engineering Lever #1

仓库级指令 · .github/copilot-instructions.md

最小动作、最大杠杆。新建一个 Markdown，整个团队、所有 IDE、所有 Chat 都自动遵守。

P.04 / 19
.github/copilot-instructions.md 
# OA System · Copilot Repository Instructions

## 项目概览
- 内部 OA 系统：审批 / 工单 / 报销 / 组织架构
- 前端: Vue 3 + TypeScript + Element Plus + Pinia
- 后端: Spring Boot 3 + MyBatis-Plus + MySQL 8

## 必须遵守的代码规范
- 所有 API 走 /oa/api/v1/**，统一返回 Result<T>
- 业务异常一律抛 BizException(code, msg)，禁止吞异常
- 数据库字段用 snake_case，Java 字段用 camelCase
- 禁止在 Controller 直接注入 Mapper

## 安全 / 审计
- 任何 update / delete 必须经过 @AuditLog 注解
- 用户输入入库前必须 XssCleaner.clean()
为什么有效

每一次 Chat 请求都会自动拼到 system prompt

不需要你每次手动复述项目规范。模型会"先读规则、再写代码"，新人上手 / 跨团队协作的代码风格自动收敛。

  • 放在仓库根： .github/copilot-instructions.md，随仓库版本管理。
  • VS Code 必须开启： github.copilot.chat.codeGeneration.useInstructionFiles: true
  • 用斜杠生成草稿： Chat 中输入 /generateInstructions，让 Copilot 扫描后吐初版。
  • 保持精炼： 一页 A4 以内，规则 > 描述。规则越多，单条权重越低。

# Frontend Rules · OA Web

- 所有页面用 <script setup lang="ts">，禁止 Options API

# MyBatis SQL Rules

- 禁止 SELECT *，列出所有字段
- 写入操作必须带 tenant_id 条件
- 软删除字段 is_deleted = 0 必须显式带上
- 大表查询必须带 LIMIT 或时间范围
- 严禁 ${} 拼接用户输入，改用 #{}

09 · Engineering Lever #6

.github/agents/planner.agent.md 
---
description: Generate an implementation plan for new features.
name: Planner
tools: ['web/fetch', 'search/codebase', 'search/usages']
model: ['Claude Opus 4.5', 'GPT-5.2']
handoffs:
  - label: Implement Plan
    agent: agent
    prompt: Implement the plan outlined above.
    send: false
---
# Planning instructions
You are in planning mode. Generate a Markdown plan with:
Overview · Requirements · Steps · Testing.
Don't make any code edits.
Frontmatter 关键字段
  • description / name — 在 agent 选择器里展示
  • tools — 白名单工具，超出范围模型无法调用
  • model — 数组 = fallback 顺序，第一个不可用退第二个
  • handoffs — 完成后自动出现的"下一步"按钮
  • agents / mcp-servers — 子 agent 与外接 MCP
存放位置 / 跨工具复用
  • .github/agents/*.agent.md — 仓库级（团队共享）
  • ~/.copilot/agents/*.agent.md — 用户级
  • .claude/agents/*.md — 同时被 Claude Code 识别
  • Chat 输入 /agents 进入 Configure 菜单

12 · Context Engineering · 02

Checkpoints · Fork · Steer · AI 时光机

会话不是一条直线。回滚、分叉、并行、引导 — Chat 是可治理的。

P.13 / 19
Checkpoints

回滚到任意历史状态

每条 prompt 都是一个 checkpoint。可跳回去、改 prompt 走另一条分支，之前的代码改动也一起回退。

Fork Session

复制独立分支会话

同一个上下文复制成两条线并行试。原会话不动，A/B 探索两个方案。

多会话并行

Sidebar 列出所有活跃 session

每个 session 独立 context window。一边跑 long task，一边新开 session 写新功能。

Send while running · 三档
  • Add to Queue — 等当前轮跑完再发
  • Steer with Message — 跑的时候插一句"别走这条路，改走 X"
  • Stop and Send — 直接打断重新开始
三条治理准则
  • 任务切换 = 新会话（避免历史污染思路）
  • 走偏 = Steer（即时纠偏，不浪费已生成内容）
  • 犯错 = Checkpoint 回滚（一键回到上一个好状态）

13 · Context Engineering · 03

Git Worktree · 让 AI 在沙箱里折腾

长任务 / 实验性重构 / 风险改动 — 一律放 worktree，主目录永远干净。

P.14 / 19

↓

WT · B

独立 bugfix 实验
WT · C

技术预研 spike

同一仓库 · 多个工作目录 · 各自分支 · 互不干扰

terminal · git worktree 常用命令 
# 新开一个并行工作目录
git worktree add ../oa-feat-a feature/a

# agent 在这里跑长任务，主目录继续工作
cd ../oa-feat-a && code .

# 单文件精准回滚（AI 改坏了）
git restore src/expense/Service.java

# 完事清理
git worktree remove ../oa-feat-a
  • Copilot CLI sessions 默认每会话一个 worktree，天然隔离
  • 频繁 commit = 廉价 checkpoint，AI 闯祸 git reset 秒回
  • git restore <path> 只回退单文件，不动其他进度
  • 配合 stash / branch，做"开发快照"

14 · Troubleshoot · Pain #02

为什么 Claude 选不到？六层逐项排查

"管理后台开了"≠"IDE 立刻能选到"。模型可见性 = Plan × Policy × Editor × Cache × Region × User。

P.15 / 19
Layer 1 · Plan

计划是否覆盖该模型

Copilot Free 不支持 Claude；Business / Enterprise 支持但需管理员开启。Pro/Pro+ 走个人开关。

Layer 2 · Policy

组织策略 → Models / Editor preview features

github.com → Org → Copilot → Policies：把 Claude Sonnet/Opus 与 Editor preview features 都置为 Allowed。

Layer 3 · Editor 版本

VS Code & Copilot Chat 必须够新

建议 VS Code ≥ 1.95 + GitHub Copilot Chat 最新稳定版；Insiders 解锁更多预览模型。

Layer 4 · 用户启用

Settings → Copilot → Manage Models

个人侧也要勾选 Enable Claude Sonnet 4.5；首次启用通常需要再点一次"Acknowledge"。

Layer 5 · 缓存 / 重启

Sign out → Sign in → Reload Window

策略生效有缓存（最长 ~30 min）。三连：Sign out Reload Sign in。

Layer 6 · Region / 状态

Public Preview / GA / 区域不可用

查 githubstatus.com & Copilot Changelog。某些 Claude 版本仅 cross-geo GA，区域受限。

⚡ 90% 的"选不到"问题止于 Layer 2 + Layer 5。先核 Policy，再 Sign-out 重启。
15 · Troubleshoot · Pain #03

响应慢 · 三层排查清单

把"慢"拆成网络 / 上下文 / 模型负载三类，分别下手。

P.16 / 19
L1 · 网络层

企业代理 / Region

  • 检查 HTTPS_PROXY / HTTP_PROXY 与 VS Code http.proxy 是否一致
  • 白名单：*.githubcopilot.com · api.github.com · copilot-proxy.githubusercontent.com
  • 开启 github.copilot.advanced.debug.useNodeFetcher 排查证书 / TLS
  • 命令面板 Developer: Toggle Developer Tools → Network 抓包看 RTT
  • 跨境团队走企业 DNS / SD-WAN，避免裸出口
L2 · 上下文层

Prompt / 文件量

  • 一次塞 20+ 文件 → 自然慢。改用 #file: 精准引用 3-5 个
  • 关闭不必要的 #codebase，必要时再开
  • 大文件先选区，再 #selection，别整文件
  • 检查 copilot-instructions.md 是否过长（>200 行明显拖慢）
  • Agent 模式工具数过多 → 收敛工具集
L3 · 模型 / 负载

选型 & 切换

  • Opus / Thinking 模型本身慢，简单任务切 Sonnet / GPT-4.1
  • 遇到 model 拥塞，用 Auto 让 Copilot 路由到健康模型
  • 看 githubstatus.com 与 Copilot Changelog 公告
  • VS Code 状态栏 Copilot 图标看是否限速 / 退避
  • 单 Chat 历史过长 → 新开 Thread，避免重发整段历史
16 · Troubleshoot · Pain #04

Bug 定位 · Before / After Prompt 对照

"AI 给的位置不对" ≈ "你没把堆栈、调用链、复现路径喂给它"。

P.17 / 19
BEFORE · 模糊提问 
报销审批通过后金额对不上，
你帮我看下哪里出了问题。
模型只能：猜测、列宽泛可能性、或随便指一个文件。
  • 没有错误信息
  • 没有触发路径
  • 没有相关文件指向
  • 没有"对不上"的具体定义
AFTER · grounded prompt 
# Bug · 报销金额错算

## 现象
审批通过后 expense.total_amount
比明细 SUM(items.amount) 少 1 分

## 复现
1. POST /oa/api/v1/expense 含 3 条明细
2. 走 approve() 流程
3. GET 返回 total = 99.99，明细求和 = 100.00

## 上下文
#codebase
#file:server/expense/ExpenseService.java
#file:server/expense/ApprovalHandler.java

## 要求
- 列出可能的 3 个根因，排序
- 指出最可疑代码行 + 调用链
- 给出最小复现单测
grounding：贴堆栈 + 文件 + 复现 让 AI 列假设而不是直接给答案 要求最小单测 = 自动验证
