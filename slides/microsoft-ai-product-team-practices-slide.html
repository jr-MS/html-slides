02 · Transformation

AI 时代的关键转型：从分段交接到并行协同

过去（角色分段）

  • PM 写文档 → 设计出稿 → 开发实现 → 测试验证
  • 交接点多，等待与返工多
  • 大多数步骤按“天/周”推进

现在（协同并行）

  • PM/设计可直接写代码与原型，研发做架构和质量把关
  • Agent 接手高重复执行环节
  • 更多步骤按“小时”推进
方向不变：围绕用户价值。变化的是执行方式、协作速度与交付介质。
03 · Product Manager

产品经理职责没变，执行方式发生跃迁

不变

持续围绕“产品 × 用户”，定义问题、价值与优先级。

变化 1

从“文档驱动”转向“代码 + 文档双驱动”，代码就是更可执行的规格。

变化 2

从串行交接转向自助交付：PM 可先完成可运行原型并提交 PR。

核心结论：PM 仍是产品与用户的桥梁，但成为了更强的 Builder。

06 · Before vs Now

从前与现在：昨天与今天的对比

从前（Yesterday）

~3 周
  • 文档是主交付物
  • 等待交接是主成本
  • PM 产出 PRD，设计产出 Figma，研发写代码

现在（Today）

~3 天
  • 代码成为主交付物之一（code as spec/design）
  • Agent 接管重复执行，人负责判断与责任
  • PM、设计、研发都在向 Builder 收敛
07 · Enablers

让变化真正发生的三个实践

01 把重复流程写成 Skill

高频动作模板化，团队可复用，不再每次从零开始。

02 把知识沉淀到代码库

环境、测试、bug 处理规范“活在仓库里”，而不是散落文档里。

03 用 Worktree 做并行开发

多任务并行推进，减少上下文切换，主分支保持干净稳定。

这三项组合起来，决定团队能否从“会用 AI”走向“AI 原生协作”。
08 · Collaboration & Writing Shift

团队内部“写作”与协作的变化

PM

从写完整 PRD 转向“轻文档 + 可运行代码”。

代码就是 Spec

设计

从只交 Figma 到交互代码与体验细节直接落地。

代码就是设计

研发

从“主写手”转向“架构与质量把关者 + 复杂问题解决者”。

工程守门
写作没有消失，而是从“描述需求”升级为“定义执行约束 + 可复用流程资产”。
09 · Engineering Boundary

研发最关键的一页：哪些交给 Agent，哪些不能

可以交给 Agent不能交给 Agent
写初版代码、生成多个备选方案判断架构是否合理、是否可维护
样式细节修改、批量重复任务决定采用哪个方案、承担最终责任
跑测试、修简单报错、整理资料判断关键风险覆盖是否充分、信息是否可信
快速 Demo / 原型验证决定是否可以进入生产环境
可以外包执行，但不能外包理解、判断与责任。
10 · Tooling Shift

工具选择的变化：从“找软件”到“定制软件”

过去

  • 市场有没有现成产品？
  • 能不能将就满足流程？

现在

  • 能否按团队工作流快速做一个“刚好够用”的小工具？
  • 通过 IDE/CLI/协作工具入口，把 Agent 接进真实流程。
微软产品团队实践中，工具能力正从“采购”转向“构建”。
11 · Design & Research

新增实践：设计师与用户调研也在走向 Builder

角色变化

  • 设计师可直接编写前端交互代码，缩短“设计→实现”链路
  • 用户调研团队可快速做实验页、问卷流、洞察分析脚本
  • 从“提需求”升级为“可执行原型共创”

团队复用机制

  • 将高频任务封装成 Skills（调研总结、可用性检查、文案生成）
  • 在团队内共享 Skill 库，复用最佳流程
  • 通过 MCP/知识库把规范和经验对齐到同一入口
这也是微软产品组的重要趋势：不同角色都在向 Builder 演进。
12 · Unified Builder Model

从不同角色，走向共同的 Builder 能力模型

业务理解

用户价值、场景和约束仍由人主导。

Agent 编排

把任务拆解给不同 agent / skill，形成流水线。

工程判断

人负责边界、风险、质量与最终决策。

“人人都是 Builder”不是人人都写同样代码，而是人人都具备可执行交付能力。
13 · Best Practices (Ref: Copilot Slides P2-P13)

可落地的最佳实践（第一组）

上下文工程优先

  • 把上下文当预算：显式引用 > 隐式猜测
  • 仓库级 copilot-instructions.md 做长期规则注入
  • 按前后端/SQL 拆分 *.instructions.md，降低噪音

能力资产化

  • 把高频提问沉淀成 Prompt Files 与 Chat Modes
  • 把团队知识接入 MCP（GitHub/Wiki/DB）
  • 用 Copilot Spaces 做跨仓库统一 grounding
14 · Best Practices (Execution)

可落地的最佳实践（第二组）

Agent 编排与边界

Plan → Implement → Review 分层；Read / Write 权限隔离；人在 handoff 节点把关。

会话治理

上下文超过 60% 主动 compact；任务切换开新会话；走偏及时 steer。

交付节奏

T+0 建规则，T+1 建模板，T+30 建 MCP 飞轮与采纳看板，纳入 DoD。

目标不是“更会提问”，而是把 AI 使用方式工程化、流程化、组织化。
15 · Closing

结论：团队角色在变化，但责任没有外包

AI 让执行更快；真正拉开差距的，是跨角色协作、工程判断与组织级复用能力。
